# Deploying to Render

The `render.yaml` Blueprint at the repo root describes the full stack:

- **Web service** `bakerydemo` — builds the Dockerfile and listens on `$PORT` (Render injects it).
- **Postgres** `bakerydemo-db` — its connection string is injected as `DATABASE_URL`.

Prerequisites: your repo is on GitHub ([see the shared setup](DEPLOYMENT.md#1-publish-the-repo)).

> You need at least [Blueprints access on the repo](https://render.com/docs/blueprint-spec#blueprint-project-setup)
> (public repos work out of the box).

## 1. One-click deploy

Once your repo is on GitHub, deploy the whole stack with:

```
https://render.com/deploy?repo=https://github.com/<your-account>/wagtail-bakerydemo-demo
```

## 2. Or via the dashboard

1. Render dashboard → **New → Blueprint** → pick your repo → **Apply**.
2. Render reads `render.yaml` and creates the services listed above.
3. First deploy sequence (watch the *Logs* tab):
   the entrypoint waits for Postgres → `migrate` → seeds the full demo site once → uWSGI starts.
4. Open `https://<service-name>.onrender.com` (site) and `/admin/` (Wagtail admin).

Render's first-build takes ~5-10 min (Python image + dependency install). Subsequent builds are much
faster thanks to caching.

## 3. Environment variables

All already generated by the Blueprint; adjust on the service's **Environment** tab:

| Variable                  | Value                                   | Notes                                                       |
|---------------------------|-----------------------------------------|-------------------------------------------------------------|
| `DATABASE_URL`            | *(set automatically from the database)* | `dj-database-url` picks it up                               |
| `DJANGO_SECRET_KEY`       | *(auto-generated)*                      | Regenerate in Environment > Change value to rotate           |
| `DJANGO_ALLOWED_HOSTS`    | `*`                                      | For a real installation: `yourdomain.example.com,.onrender.com` |
| `DJANGO_LOAD_INITIAL_DATA`| `on`                                    | Demo content seeded only when the site is empty (see `docker-entrypoint.sh`) |

## 4. Free-tier notes

- Free web services **sleep after 15 minutes** of no traffic and take ~1 min to wake up.
- Free Postgres **expires after 30 days** — upgrade the database plan (or dump + restore) to keep data.
- 512 MB RAM per instance; the demo runs fine with uwsgi's 2 workers / 4 threads.
- Change instance type: web service → *Settings → Instance Type*.

## 5. Updating

Push to your repo → Render auto-deploys. Migrations run automatically on each start
(from `docker-entrypoint.sh`).
